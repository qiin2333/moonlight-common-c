# Live MAT transport boundary - 2026-10-23

This PR targets **mic**. It owns negotiation, authenticated live transport,
bounded reassembly and synchronous cycle/EOS callbacks. It does not own files,
offline input, native capture, encoding or hardware rendering.

- Codec 7 / `mat-live-v1` uses HKDF-SHA256, AES-128-GCM with authenticated headers
  and a 64-bit packet counter. RTP/FEC operates on ciphertext; authentication
  precedes reassembly. Loss, corruption, gaps and consumer failure are terminal.
- Local MAT preference 6 selects live7 or Opus0 before ANNOUNCE. After selection
  there is no codec change. Removed finite codec IDs 4/5 fail before networking;
  they are reserved and must not be reused. Old finite-only hosts cause AUTO to
  select Opus; stale or mismatched MAT acknowledgements fail the handshake.
- Carrier `iec61937-192000-8-s16le` carries 61,440 bytes per 20 ms cycle. The SMAT
  clock is 48,000 Hz / 960 ticks per cycle. RTP fragment ticks are not media PTS.
- `LiSetMatPlaybackCallbacks` registers the live consumer during audio init and
  is cleared after threads join. Consumers copy borrowed bytes before returning;
  zero means failure. The end callback requires authenticated, complete END and
  must finish any bounded drain before returning success. Closing or timing out
  cannot synthesize successful EOS.
- The two-second watchdog measures accepted live input. It stops only after
  verified END, before the consumer drain. Its timestamp is loaded before the
  clock to avoid racing a newer publication. Unrelated Opus behavior is retained.
- Finite profile negotiation, SHA/count receiver, recording APIs and finish
  polling are removed. Standalone file checks and mock offline input live in the
  parent Sunshine `spatial-object-spike/mat-diagnostics` directory.

Static CTest has 13 tests, including live callback failures, missing END timeout,
drain semantics, RTP wrap/FEC, authenticated integrity and strict RTSP parser
uniqueness. Windows CI also builds/runs static tests with MSVC C11 atomics.
Parent software acceptance adds an independent crypto oracle, actual UDP receive
threads, controlled RTSP negotiation, source/pipe contracts and diagnostics.

Rebuild consumers after these unpublished API removals. The historical Android
app remains pinned to its previous shared revision; current clients are mocks.
Generated bytes establish software behavior only. Earlier finite replay/native
reports do not establish current native capture, hardware playback or Atmos
recognition. Historical APIs/results are available in Git history.
